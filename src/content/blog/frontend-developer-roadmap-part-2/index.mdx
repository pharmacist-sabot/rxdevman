# Frontend Developer Roadmap (Part 2): Vue.js

สวัสดีครับนักพัฒนาทุกท่าน ยินดีต้อนรับสู่ตอนที่ 2 ของซีรีส์ **"Frontend Developer Roadmap"**

ในตอนนี้ เราจะมาเจาะลึก **Vue.js** - หนึ่งในเฟรมเวิร์ก JavaScript ที่ได้รับความนิยมสูงสุดในโลก ด้วยความ **เรียบง่าย ยืดหยุ่น และเข้าใจง่าย** โดยเฉพาะสำหรับผู้เริ่มต้น

Vue.js ไม่ได้เป็นแค่ทางเลือก แต่เป็น **ทางออกที่ทรงพลัง** สำหรับทั้งโปรเจกต์เล็กและองค์กรขนาดใหญ่ โดยเฉพาะในจีน ยุโรป และกลุ่มผู้พัฒนาที่ชื่นชอบความชัดเจนและควบคุมได้

บทความนี้ออกแบบมาเพื่อให้คุณ:
- เข้าใจ Vue.js อย่างลึกซึ้ง ไม่ใช่แค่ "ใช้ได้"
- รู้ว่า Vue จัดการ reactivity อย่างไร
- เข้าใจความต่างระหว่าง Options API และ Composition API
- รู้จักเครื่องมือใน Ecosystem ที่จำเป็น
- เตรียมความพร้อมสำหรับการใช้ Vue ร่วมกับ Nuxt.js (ในบทความต่อไป)

<InfoBox title="Pro Tip!">
  Vue.js ถูกออกแบบมาเพื่อ <strong>เรียนรู้ง่าย</strong> และ <strong>เริ่มใช้งานได้ทันที</strong> แม้จะแค่แทรกใน HTML ผ่าน &lt;script&gt; ก็สามารถใช้งานได้แล้ว
</InfoBox>

## Vue.js คืออะไร?

**Vue.js** (อ่านว่า "วิว" /vjuː/) คือ เฟรมเวิร์ก JavaScript สำหรับสร้าง User Interface (UI) ที่ใช้งานง่ายและทรงพลัง

Vue ถูกออกแบบมาให้เป็น **"Progressive Framework"** ซึ่งเป็นหัวใจสำคัญที่ทำให้มันยืดหยุ่นสูง

<InfoBox title="💡 Progressive Framework คืออะไร?">
  หมายความว่าคุณสามารถเริ่มต้นใช้ Vue แค่ส่วนเล็กๆ ในโปรเจกต์ของคุณ (เช่น ทำแค่ Widget แสดงผลข้อมูล) แล้วค่อยๆ ขยายการใช้งานไปสู่เครื่องมืออื่นๆ ใน Ecosystem ของ Vue (เช่น `Vue Router`, `Pinia`) เมื่อโปรเจกต์มีความซับซ้อนมากขึ้น โดยไม่จำเป็นต้องนำทั้งระบบเข้ามาใช้ตั้งแต่แรก
</InfoBox>

## แนวคิดหลักของ Vue.js

หัวใจของ Vue คือการเปลี่ยนมุมมองการพัฒนาเว็บ จากเดิมที่เราต้อง **สั่ง** ให้เบราว์เซอร์ทำอะไรทีละขั้นตอน (Imperative) มาเป็นการ **บอก** ว่าผลลัพธ์สุดท้ายควรมีหน้าตาอย่างไร (Declarative)

แนวคิดนี้ทำให้เราเขียนโค้ดที่เข้าใจง่ายและบำรุงรักษาง่ายขึ้นมาก

### 1. Declarative Rendering (การแสดงผลเชิงพรรณนา)

แทนที่จะเขียนโค้ดเพื่อเข้าไปจัดการ DOM โดยตรง (เช่น การใช้ `document.getElementById`) Vue เปิดให้เราใช้ Template Syntax ที่คล้าย HTML เพื่อ "พรรณนา" หรือ "ประกาศ" ว่า UI ควรมีหน้าตาอย่างไรเมื่อข้อมูล (State) เป็นค่านั้นๆ

<InfoBox title="เปรียบเทียบ: Imperative vs. Declarative">
  <ul>
    <li>
      <strong>Imperative (เชิงคำสั่ง):</strong> "ไปที่ Element ที่มี id 'app', จากนั้นเปลี่ยนข้อความข้างในเป็น 'สวัสดี Vue!'" (นี่คือวิธีของ JavaScript ปกติ)
    </li>
    <li>
      <strong>Declarative (เชิงพรรณนา):</strong> "ใน Element ที่มี id 'app', ข้อความ `message` จะต้องแสดงผลตรงนี้เสมอ" (นี่คือวิธีของ Vue)
    </li>
  </ul>
</InfoBox>

ดูตัวอย่างโค้ดนี้:

```html
<!-- index.html -->
<script src="https://unpkg.com/vue@3"></script>

<div id="app">
  <h1>{{ message }}</h1>
</div>

<script>
  // app.js
  const { createApp } = Vue

  createApp({
    data() {
      return {
        message: 'สวัสดี Vue!'
      }
    }
  }).mount('#app')
</script>
```

จากโค้ดด้านบน เราเพียงแค่ ประกาศ (Declare) ว่าต้องการให้ข้อความใน message แสดงผลอยู่ภายในแท็ก < h1> เท่านั้น
ส่วนที่เหลือ... Vue จะจัดการเองทั้งหมด เมื่อค่าของ message เปลี่ยนแปลงในอนาคต DOM ก็จะอัปเดตตามโดยอัตโนมัติ ซึ่งเป็นหัวใจของระบบ Reactivity

<InfoBox title="✅ Key Takeaway" variant="success">
เราไม่ต้องยุ่งกับการจัดการ DOM ที่ซับซ้อนอย่าง `document.getElementById(...).innerText = ...` อีกต่อไป ทำให้เราสามารถโฟกัสกับ Logic ของแอปพลิเคชันได้อย่างเต็มที่
</InfoBox>

### 2. Component-Based Architecture (สถาปัตยกรรมเชิงคอมโพเนนต์)

เมื่อแอปพลิเคชันมีขนาดใหญ่ขึ้น การจัดการโค้ด HTML, CSS และ JavaScript ที่กองรวมกันอยู่ในไฟล์ใหญ่ๆ จะกลายเป็นฝันร้ายทันที

Vue แก้ปัญหานี้โดยให้เราแตก UI ทั้งหมดออกเป็นชิ้นส่วนเล็กๆ ที่ทำงานแยกกันและนำกลับมาใช้ซ้ำได้ ที่เรียกว่า **Component**

<InfoBox title="💡 คิดภาพตาม">
  ลองนึกถึงหน้าเว็บเหมือนการต่อเลโก้:
  <ul>
    <li>**Component** คือ **ตัวต่อเลโก้** หนึ่งชิ้น (เช่น ปุ่ม, ช่องค้นหา, การ์ดแสดงสินค้า)</li>
    <li>**หน้าเว็บ** คือ **ปราสาทเลโก้** ที่เกิดจากการนำตัวต่อแต่ละชิ้นมาประกอบกัน</li>
  </ul>
  เราสามารถสร้าง "ปุ่ม" (Component) แค่ครั้งเดียว แล้วนำไปใช้ซ้ำกี่ครั้งก็ได้ทั่วทั้งเว็บไซต์
</InfoBox>

ความมหัศจรรย์ของ Vue คือการรวมทุกอย่างที่เกี่ยวกับ Component หนึ่งๆ ไว้ในไฟล์เดียว ที่เรียกว่า **Single-File Component (SFC)** ซึ่งจะมีนามสกุลเป็น `.vue`

```vue
// src/components/MyButton.vue

<template>
  <button class="btn" :class="`btn-${variant}`" @click="$emit('action')">
    <slot /> <!-- แสดงข้อความหรือไอคอนที่ส่งเข้ามา -->
  </button>
</template>

<script setup>
// Vue 3 Composition API style
defineProps({
  variant: {
    type: String,
    default: 'primary' // 'primary' or 'secondary'
  }
})

defineEmits(['action'])
</script>

<style scoped>
/* สไตล์เหล่านี้จะถูกจำกัดให้ใช้แค่ใน Component นี้เท่านั้น */
.btn {
  padding: 0.5rem 1rem;
  border: none;
  border-radius: 6px;
  font-weight: 600;
  cursor: pointer;
  transition: transform 0.1s ease-in-out;
}
.btn:hover {
  transform: scale(1.05);
}
.btn-primary {
  background-color: var(--brand-color);
  color: white;
}
.btn-secondary {
  background-color: var(--card-border-color);
  color: var(--font-color);
}
</style>
```

<CodeExplainer title="เจาะลึกโครงสร้างไฟล์ .vue">
<details>
<summary><strong>&lt;template&gt;</strong> - ส่วนของโครงสร้าง (HTML)</summary>
<p>
เป็นส่วนที่กำหนดหน้าตาและโครงสร้างของ Component เราสามารถใช้ HTML มาตรฐานร่วมกับ Syntax พิเศษของ Vue เช่น <code>:class</code> (สำหรับ Dynamic Binding) หรือ <code>@click</code> (สำหรับ Event Handling) ได้
</p>
</details>
<details>
<summary><strong>&lt;script&gt;</strong> - ส่วนของตรรกะ (JavaScript)</summary>
<p>
เป็นส่วนที่จัดการ Logic, ข้อมูล (Data), และสถานะ (State) ของ Component ในตัวอย่างนี้เราใช้ <code>defineProps</code> เพื่อรับค่าจากภายนอก และ <code>defineEmits</code> เพื่อส่ง Event กลับออกไป
</p>
</details>
<details>
<summary><strong>&lt;style scoped&gt;</strong> - ส่วนของสไตล์ (CSS)</summary>
<p>
เป็นส่วนที่กำหนดสไตล์ให้กับ Component จุดเด่นคือคำว่า <code>scoped</code> ที่จะบังคับให้ CSS เหล่านี้มีผล<strong>เฉพาะกับ Component นี้เท่านั้น</strong> ไม่รั่วไหลไปกระทบส่วนอื่นของเว็บไซต์!
</p>
</details>
</CodeExplainer>

<InfoBox title="✅ Key Takeaway" variant="success">
การรวม HTML, CSS, และ JavaScript ที่เกี่ยวข้องกันไว้ในไฟล์ `.vue` ไฟล์เดียว ทำให้โค้ดของเราเป็นระเบียบสูง ค้นหาง่าย และบำรุงรักษาได้สะดวกอย่างไม่น่าเชื่อ
</InfoBox>

### 3. Reactivity System (ระบบปฏิกิริยาตอบสนอง)

นี่คือ "เวทมนตร์" ที่ทำให้ Vue โดดเด่นและใช้งานง่ายอย่างไม่น่าเชื่อ แทนที่เราจะต้องคอยสั่งให้ UI อัปเดตทุกครั้งที่ข้อมูลเปลี่ยน Vue จะทำหน้าที่เป็นเหมือนผู้ช่วยที่คอย "จับตาดู" ข้อมูลของเรา และเมื่อข้อมูลนั้นเปลี่ยนแปลง Vue จะอัปเดตหน้าจอให้โดยอัตโนมัติ

#### ทำงานอย่างไรเบื้องหลัง?

เบื้องหลังเวทมนตร์นี้คือเทคโนโลยีของ JavaScript ที่เรียกว่า **Proxy**

<InfoBox title="💡 เปรียบเทียบให้เห็นภาพ: Vue คือผู้จัดการข้อมูลส่วนตัว">
  <ol>
    <li>
      <strong>ขั้นตอนที่ 1 (ลงทะเบียน):</strong> เมื่อ Component ของคุณแสดงผลครั้งแรกและมีการเรียกใช้ข้อมูล เช่น `count` ผู้จัดการ (Vue) จะแอบจดลงในสมุดบันทึกทันทีว่า "โอเค, Component ชิ้นนี้สนใจข้อมูล `count` อยู่นะ" - นี่คือการ **ติดตาม Dependency (Dependency Tracking)**
    </li>
    <li>
      <strong>ขั้นตอนที่ 2 (ตรวจจับการเปลี่ยนแปลง):</strong> เมื่อมีโค้ดส่วนไหนก็ตามมาเปลี่ยนแปลงค่าของ `count` ผู้จัดการ (Vue) จะรู้ทันที เพราะทุกการเข้าถึงข้อมูลจะต้องผ่านเขา (ผ่าน Proxy)
    </li>
    <li>
      <strong>ขั้นตอนที่ 3 (แจ้งเตือนให้อัปเดต):</strong> ผู้จัดการจะเปิดสมุดบันทึกดู แล้วส่งข้อความไปหาทุก Component ที่เคยลงทะเบียนไว้ว่าสนใจ `count` แล้วบอกว่า "เฮ้! ค่า `count` ที่คุณสนใจเปลี่ยนไปแล้วนะ อัปเดตตัวเองด่วน!" - นี่คือการ **Trigger Re-render**
    </li>
  </ol>
</InfoBox>

ลองดูตัวอย่าง Component Counter ง่ายๆ นี้:

```vue
<script setup>
import { ref } from 'vue'

// 1. ประกาศ state 'count' ที่เป็น reactive
const count = ref(0)

function increment() {
  // 3. เมื่อเราเปลี่ยนค่า .value, Vue จะรู้ทันที
  count.value++
}
</script>

<template>
  <!-- 2. เมื่อ template อ่านค่า count, Vue จะจดไว้ว่า UI ส่วนนี้ผูกกับ count -->
  <p>Count is: {{ count }}</p>
  <button @click="increment">Click me</button>
</template>
```

<InfoBox title="ตัวอย่างการทำงานของ Reactivity" variant="success">
จากโค้ดด้านบน...
<ul>
<li>
สมมติคุณมี <code>count</code> ใน data (ซึ่งถูกสร้างด้วย <code>ref(0)</code>)
</li>
<li>
เมื่อคุณเขียน <code>{`{{ count }}`}</code> ใน template, Vue จะทำการ 'ลงทะเบียน' ทันทีว่า "ย่อหน้า <code>&lt;p&gt;</code> นี้ผูกอยู่กับข้อมูล <code>count</code> นะ"
</li>
<li>
เมื่อคุณคลิกปุ่มและฟังก์ชัน <code>increment</code> ทำงาน ทำให้ค่า <code>count.value</code> เปลี่ยนจาก 0 เป็น 1...
</li>
<li>
Vue จะรู้ทันทีและสั่งให้<strong>เฉพาะส่วน</strong> <code>{`{{ count }}`}</code> นั้นอัปเดตตัวเองเป็นค่าใหม่บนหน้าจอ โดยไม่ไปยุ่งกับส่วนอื่นเลย!
</li>
</ul>
</InfoBox>

<InfoBox title="✅ Key Takeaway" variant="success">
หัวใจของ Reactivity คือการทำงานให้ **น้อยที่สุดและตรงจุดที่สุด** Vue ไม่ได้วาดหน้าจอใหม่ทั้งหมด แต่จะอัปเดตเฉพาะ Element ที่ข้อมูลเกี่ยวข้องมีการเปลี่ยนแปลงเท่านั้น ซึ่งเป็นเหตุผลที่ทำให้แอปพลิเคชันที่สร้างด้วย Vue ทำงานได้รวดเร็วและมีประสิทธิภาพสูง
</InfoBox>

## Options API vs Composition API

Vue มีรูปแบบการเขียน Component ให้เราเลือกใช้ 2 สไตล์หลัก ซึ่งแต่ละแบบมีจุดเด่นและเหมาะกับสถานการณ์ที่แตกต่างกัน เรามาเริ่มจากสไตล์ดั้งเดิมกันก่อน

### 1. Options API - คลาสสิก, จัดระเบียบเหมือนชั้นวางหนังสือ

นี่คือสไตล์การเขียนแบบดั้งเดิมของ Vue ที่เป็นที่รู้จักและรักใคร่ของนักพัฒนามานาน เหมาะอย่างยิ่งสำหรับผู้เริ่มต้นและโปรเจกต์ขนาดเล็กถึงกลาง เพราะมีโครงสร้างที่ชัดเจนและบังคับให้เราจัดระเบียบโค้ดเป็นหมวดหมู่

<InfoBox title="💡 คิดภาพตาม: การกรอกแบบฟอร์ม">
  การเขียน Component ด้วย Options API เหมือนกับการกรอกแบบฟอร์มที่มีช่องต่างๆ มาให้เรียบร้อยแล้ว:
  <ul>
    <li>ช่องสำหรับข้อมูล: `data`</li>
    <li>ช่องสำหรับฟังก์ชัน: `methods`</li>
    <li>ช่องสำหรับข้อมูลที่คำนวณได้: `computed`</li>
    <li>ช่องสำหรับ Lifecycle Hooks: `mounted`, `created`, `updated`</li>
  </ul>
  หน้าที่ของเราคือเติมโค้ดลงไปในช่องที่ถูกต้องเท่านั้นเอง
</InfoBox>

นี่คือตัวอย่าง Component Counter ที่เขียนด้วย Options API:

```javascript
// src/components/Counter.vue (Options API)

export default {
  // 1. "ข้อมูล" ทั้งหมดของ Component
  data() {
    return {
      count: 0
    }
  },
  // 2. "ฟังก์ชัน" ทั้งหมดที่ใช้ใน Component
  methods: {
    increment() {
      // ใช้ 'this' เพื่อเข้าถึงข้อมูลใน data
      this.count++
    }
  },
  // 3. "ข้อมูลที่ต้องคำนวณ" ค่าจะเปลี่ยนตาม data ที่ผูกไว้
  computed: {
    double() {
      return this.count * 2
    }
  },
  // 4. "Lifecycle Hook" ฟังก์ชันที่จะรันเมื่อถึงช่วงชีวิตที่กำหนด
  mounted() {
    console.log(`The initial count is ${this.count}. Component is ready!`)
  }
}
```

<CodeExplainer title="เจาะลึกแต่ละ Option">
<details>
<summary><strong>`data()`</strong></summary>
<p>
เป็นฟังก์ชันที่ต้อง return object ซึ่งบรรจุ "State" หรือข้อมูลทั้งหมดที่ Component นี้ต้องใช้ Vue จะทำให้ข้อมูลทั้งหมดในนี้เป็น Reactive โดยอัตโนมัติ
</p>
</details>
<details>
<summary><strong>`methods`</strong></summary>
<p>
เป็น object ที่เก็บฟังก์ชันทั้งหมดที่เราต้องการใช้ใน Component เช่น ฟังก์ชันที่ถูกเรียกเมื่อมีการคลิกปุ่ม
</p>
</details>
<details>
<summary><strong>`computed`</strong></summary>
<p>
ใช้สำหรับข้อมูลที่ต้องคำนวณจาก State อื่นๆ Vue จะคำนวณค่านี้ใหม่ก็ต่อเมื่อ State ที่มันอ้างอิงถึงมีการเปลี่ยนแปลงเท่านั้น (Cached) ทำให้มีประสิทธิภาพสูง
</p>
</details>
<details>
<summary><strong>`mounted()`</strong></summary>
<p>
เป็นหนึ่งใน "Lifecycle Hooks" ซึ่งเป็นฟังก์ชันที่จะถูกเรียกในช่วงเวลาต่างๆ ของ Component โค้ดใน `mounted` จะทำงานหลังจากที่ Component ถูกสร้างและแสดงผลบนหน้าจอเรียบร้อยแล้ว
</p>
</details>
</CodeExplainer>

<ProsCons>
<ul slot="pros">
<li><strong>โครงสร้างชัดเจน:</strong> บังคับให้แยกโค้ดเป็นหมวดหมู่ ทำให้ง่ายต่อการเรียนรู้และหาว่าโค้ดส่วนไหนทำอะไร</li>
<li><strong>อ่านง่ายสำหรับคนอื่น:</strong> ใครที่เคยเขียน Vue มาก่อน จะเข้าใจโครงสร้างนี้ได้ทันที</li>
<li><strong>`this` ที่ใช้งานง่าย:</strong> การเข้าถึงข้อมูลและเมธอดทำได้ง่ายผ่าน `this`</li>
</ul>
<ul slot="cons">
<li><strong>Logic กระจัดกระจาย:</strong> เมื่อ Component ใหญ่ขึ้น Logic ที่เกี่ยวกับฟีเจอร์เดียวกัน (เช่น การจัดการ User) จะถูกแยกไปอยู่ตาม `data`, `methods`, `computed` ทำให้ตามโค้ดยาก</li>
<li><strong>ยากต่อการนำ Logic กลับมาใช้ซ้ำ (Reuse):</strong> การจะแชร์ Logic ระหว่าง Component (เช่น Logic การ Fetch ข้อมูล) ทำได้ค่อนข้างลำบากและต้องใช้วิธีที่ซับซ้อนกว่า (Mixins)</li>
</ul>
</ProsCons>

### 2. Composition API - ยืดหยุ่น, ทรงพลัง, จัดระเบียบตามฟีเจอร์

จำข้อจำกัดของ Options API ที่ว่าเมื่อ Component ใหญ่ขึ้น Logic ที่เกี่ยวข้องกันมักจะกระจัดกระจายไปคนละทิศคนละทางได้ไหมครับ? **Composition API** ถูกสร้างขึ้นมาเพื่อแก้ปัญหานี้โดยตรงครับ

มันคือสไตล์การเขียนแบบใหม่ที่แนะนำใน Vue 3 ซึ่งเปิดให้เรา **จัดกลุ่มโค้ดตามฟังก์ชันการทำงาน (Logical Concern)** แทนที่จะจัดกลุ่มตามประเภทของ Option

<InfoBox title="💡 คิดภาพตาม: โต๊ะทำงานของเชฟ">
  ถ้า Options API คือ "ชั้นวางหนังสือ" ที่ทุกอย่างถูกจัดตามหมวดหมู่ (ข้อมูล, ฟังก์ชัน), Composition API ก็เหมือนกับ "โต๊ะทำงานของเชฟ" (Mise en place) ที่ส่วนผสมและเครื่องมือทั้งหมดสำหรับ "เมนูหนึ่งจาน" (ฟีเจอร์หนึ่งอย่าง) จะถูกนำมารวมกันไว้ในที่เดียว ทำให้หยิบใช้ง่ายและทำงานได้คล่องตัว
</InfoBox>

#### วิธีการเขียนแบบดั้งเดิม: ใช้ `setup()`

ในยุคแรกของ Vue 3 เราจะใส่ Logic ทั้งหมดไว้ในฟังก์ชันพิเศษที่ชื่อว่า `setup()`

```javascript
// Composition API with setup() function
import { ref, computed, onMounted } from 'vue';

export default {
  setup() {
    // --- Feature: Counter Logic ---
    const count = ref(0);
    const double = computed(() => count.value * 2);
    function increment() {
      count.value++;
    }
    // --- End of Feature ---
    
    onMounted(() => {
      console.log('Component is ready!');
    });

    // ต้อง return ทุกอย่างที่ต้องการให้ template ใช้งาน
    return {
      count,
      double,
      increment
    };
  }
}
```

วิธีที่แนะนำและทันสมัยที่สุด: ใช้ `<script setup>`
เพื่อลดความซ้ำซ้อนและทำให้โค้ดสั้นลงไปอีก Vue ได้แนะนำ Syntax แบบใหม่ที่เรียกว่า `<script setup>` ซึ่งกลายเป็นมาตรฐานในปัจจุบัน

```vue
<!-- MyCounter.vue (Recommended Way) -->
<script setup>
import { ref, computed, onMounted } from 'vue';

// ทุกตัวแปรหรือฟังก์ชันที่ประกาศตรงนี้
// จะสามารถใช้งานใน <template> ได้โดยอัตโนมัติ

const count = ref(0);
const double = computed(() => count.value * 2);

function increment() {
  count.value++;
}

onMounted(() => {
  console.log(`The initial count is ${count.value}.`);
});
</script>

<template>
  <div>
    <p>Count: {{ count }}</p>
    <p>Double: {{ double }}</p>
    <button @click="increment">เพิ่ม</button>
  </div>
</template>
```

<CodeExplainer title="ทำไม <script setup> ถึงดีกว่า?">
<details>
<summary><strong>เขียนน้อยกว่ามาก (Less Code)</strong></summary>
<p>
โค้ดสั้นลงอย่างเห็นได้ชัด ไม่ต้องมี `export default` หรือ `setup()` ครอบอีกชั้น
</p>
</details>
<details>
<summary><strong>ไม่ต้องมี `return`</strong></summary>
<p>
นี่คือข้อดีที่ใหญ่ที่สุด! ทุกตัวแปร, ฟังก์ชัน, หรือ `computed` ที่เราสร้างใน <code>&lt;script setup&gt;</code> จะถูกส่งต่อไปยัง <code>&lt;template&gt;</code> โดยอัตโนมัติ ทำให้โค้ดสะอาดตาและลดโอกาสเกิดข้อผิดพลาดจากการลืม `return`
</p>
</details>
<details>
<summary><strong>ทำงานร่วมกับ TypeScript ได้ดีเยี่ยม</strong></summary>
<p>
การกำหนด Type ให้กับ `props` และ `emits` ทำได้ง่ายและเป็นธรรมชาติกว่ามาก
</p>
</details>
</CodeExplainer>

<InfoBox title="Pro Tip!" variant="success">
หากคุณเริ่มต้นกับ Vue 3 วันนี้ ให้ใช้ <code>&lt;script setup&gt;</code> เป็นมาตรฐานได้เลย มันคืออนาคตของการเขียน Vue Component ที่ทั้งกระชับ, ทรงพลัง, และเป็นมิตรกับนักพัฒนา
</InfoBox>

<ProsCons>
<ul slot="pros">
<li><strong>จัดระเบียบตามฟีเจอร์:</strong> โค้ดที่เกี่ยวข้องกันจะอยู่ด้วยกันเสมอ ทำให้ง่ายต่อการบำรุงรักษาในโปรเจกต์ขนาดใหญ่</li>
<li><strong>นำ Logic กลับมาใช้ซ้ำได้ดีเยี่ยม:</strong> เราสามารถแยก Logic ออกไปเป็นฟังก์ชันที่ใช้ซ้ำได้ (เรียกว่า "Composables") เช่น <code>useFetch()</code>, <code>useMousePosition()</code> ซึ่งเป็นจุดแข็งที่สำคัญที่สุด</li>
<li><strong>ยืดหยุ่นสูง:</strong> ไม่มีโครงสร้างที่ตายตัว ทำให้เราออกแบบการจัดการ State ได้อย่างอิสระ</li>
<li><strong>Type Inference ดีขึ้น:</strong> ทำงานร่วมกับ TypeScript ได้อย่างราบรื่น</li>
</ul>
<ul slot="cons">
<li><strong>Learning Curve สูงกว่าเล็กน้อย:</strong> สำหรับผู้เริ่มต้น อาจจะรู้สึกอิสระเกินไปและต้องทำความเข้าใจแนวคิด Reactivity (เช่น `ref`, `reactive`, `.value`) มากขึ้น</li>
<li><strong>ต้องจัดการเองมากขึ้น:</strong> ความยืดหยุ่นต้องแลกมากับการที่ไม่มี "กรอบ" มาบังคับ ทำให้สไตล์การเขียนในทีมอาจแตกต่างกันได้หากไม่มีการตกลงกัน</li>
</ul>
</ProsCons>

## Vue Directives: คำสั่งพิเศษใน HTML

Vue มี **Directives** - คำสั่งที่ขึ้นต้นด้วย `v-` ที่ช่วยเพิ่มพลังให้ HTML

- `v-model`  ผูกข้อมูลสองทาง (Two-way Binding) 
- `v-if` / `v-show` แสดง/ซ่อน element 
- `v-for` วนลูปแสดงรายการ
- `v-on` (`@`) จับ event เช่น click, input
- `v-bind` (`:`) ผูก attribute แบบไดนามิก

```vue
<input v-model="search" placeholder="ค้นหา..." />
<ul>
  <li v-for="user in filteredUsers" :key="user.id">
    {{ user.name }}
  </li>
</ul>
<button @click="save">บันทึก</button>
<div v-if="loading">กำลังโหลด...</div>
```

> 💡 `v-if` ลบ element ออกจาก DOM, `v-show` แค่ซ่อนด้วย CSS - เลือกใช้ตามความถี่ของการสลับ


### 🧠 Pinia - State Management 

แทน Vuex รุ่นใหม่ เขียนง่าย ใช้กับ Composition API ได้ดี

```js
// stores/counter.js
import { defineStore } from 'pinia';

export const useCounterStore = defineStore('counter', {
  state: () => ({
    count: 0
  }),
  actions: {
    increment() {
      this.count++;
    }
  },
  getters: {
    double: (state) => state.count * 2
  }
});
```

```vue
<script setup>
import { useCounterStore } from '@/stores/counter';
const counter = useCounterStore();
</script>

<template>
  <button @click="counter.increment">
    Count: {{ counter.count }}
  </button>
</template>
```

> ✅ ไม่ต้องจำ `commit`, `dispatch` - ใช้ `actions` โดยตรง
