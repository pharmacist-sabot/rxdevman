สำหรับใครที่เพิ่งเริ่มเขียน Rust น่าจะเคยสงสัยว่า ทำไม `println!` ถึงมีเครื่องหมาย `!` ต่อท้าย ต่างจาก `printf` ของ C หรือ `console.log` ของ JavaScript ตรงไหน ทำไมถึงไม่เรียกมันว่าเป็น function ปกติ เครื่องหมาย `!` นั้นมีความหมายลึกกว่าที่คิดมาก เพราะมันบอกเราว่าสิ่งนี้ไม่ใช่ function แต่เป็น **macro** ซึ่งเป็นหนึ่งใน feature ที่ทรงพลังที่สุดของ Rust

---

## println! ไม่ใช่ function แต่เป็น macro

`println!` ไม่ใช่ function ปกติ แต่เป็น **declarative macro** ที่ถูกนิยามไว้ใน standard library ด้วย `macro_rules!` ความแตกต่างที่สำคัญคือ function จะถูก run ในขณะ runtime แต่ macro จะถูก **expand** ในขณะ compile time นั่นหมายความว่า code ที่เราเขียนจะถูก transform ไปเป็น code อื่นก่อนที่ compiler จะเห็นจริงๆ

ถ้าเราลอง expand `println!("Hello, world!")` ด้วย `cargo expand` จะพบว่ามันถูกแปลงไปเป็นแบบนี้

```rust
#![feature(prelude_import)]
extern crate std;
#[prelude_import]
use std::prelude::rust_2024::*;
fn main() {
    {
        ::std::io::_print(format_args!("Hello, world!\n"));
    };
}
```

พูดง่ายๆ คือ `println!` ถูก expand ให้เรียก `format_args!` macro เพื่อสร้าง `fmt::Arguments` object แล้วส่งต่อให้ internal function ชื่อ `std::io::_print` เพื่อทำงานจริงๆ นั่นเอง

---

## ทำไมต้องเป็น macro ทำไมถึงเป็น function ไม่ได้

ถ้า `println!` เป็น function ธรรมดา เราจะเจอปัญหาหลายอย่างที่ macro ช่วยแก้ได้:

<FeatureGrid>
  <FeatureCard title="จำนวน argument ที่ไม่ตายตัว" icon="list-bullet">
    function ของ Rust ต้องประกาศ parameter ไว้ตอน compile time แต่ <code>println!</code> สามารถรับ argument ได้จำนวนเท่าไหร่ก็ได้ เช่น <code>println!("a")</code>, <code>println!("{} {}", x, y)</code>, <code>println!("{} {} {}", a, b, c)</code> macro สามารถจัดการ variadic arguments ได้ง่ายกว่ามาก
  </FeatureCard>
  <FeatureCard title="Auto-referencing" icon="command-line">
    macro สามารถสร้าง code ที่ auto-borrow ให้ได้ ทำให้เราไม่ต้องเขียน <code>&name</code> เอง ตัวแปรยังใช้ต่อได้โดยไม่ต้องกังวลเรื่อง ownership
  </FeatureCard>
  <FeatureCard title="Compile-time format string validation" icon="check-badge">
    ถ้าเขียน <code>println!("{}", x, y)</code> ที่มี argument เกิน หรือ syntax ผิด compiler จะจับ error ได้ตั้งแต่ตอน compile ไม่ใช่ตอน run
  </FeatureCard>
  <FeatureCard title="String literal ถูก parse ในขณะ compile" icon="code-bracket">
    format string ถูก parse ในขณะ compile time ทำให้ compiler รู้ว่า placeholder ตรงไหนตรงกับ argument ตัวไหน และ optimize ได้มากกว่า
  </FeatureCard>
</FeatureGrid>

### Auto-referencing ทำงานอย่างไร?

ลองดูตัวอย่างนี้

```rust
let name = String::from("Rust");
println!("{}", name);
println!("{}", name);
```

ถ้าเป็น function ปกติ การเรียก `println!("{}", name)` ครั้งที่สองน่าจะมีปัญหาเรื่อง ownership เพราะ `name` น่าจะถูก move ไปแล้ว แต่ macro สามารถสร้าง code ที่ auto-borrow ให้ได้ ทำให้ `name` ยังใช้ได้ต่อโดยไม่ต้องเขียน `&name`

## ตระกูล println!

`println!` ไม่ได้อยู่ตัวเดียว มันเป็นส่วนหนึ่งของ macro family ที่ทำงานบนพื้นฐานเดียวกัน

- **`print!`** - เหมือน `println!` แต่ไม่ใส่ newline
- **`println!`** - พิมพ์ + newline
- **`eprint!`** - พิมพ์ไปที่ stderr ไม่มี newline
- **`eprintln!`** - พิมพ์ไปที่ stderr + newline
- **`format!`** - สร้าง String กลับมา ไม่ได้พิมพ์
- **`write!`** - เขียนไปที่ buffer ที่ระบุ
- **`writeln!`** - เขียนไปที่ buffer + newline

ทุกตัวล้วนแล้วแต่ใช้ `format_args!` เป็นแกนหลักในการทำงาน ต่างกันแค่ว่าจะส่ง output ไปที่ไหน

## ลงมือใช้งาน

วิธีใช้งาน `println!` นั้นง่ายมากครับ

```rust
fn main() {
    // ไม่มี argument
    println!();

    // string ตรงๆ
    println!("Hello, world!");

    // ใช้ placeholder
    println!("My name is {}", "Bond");

    // หลาย argument
    println!("{} is {} years old", "Alice", 30);

    // named arguments
    println!("{subject} {verb} {object}",
        subject = "The quick brown fox",
        verb = "jumps over",
        object = "the lazy dog"
    );

    // Debug format
    println!("Debug: {:?}", vec![1, 2, 3]);

    // Pad with zeros
    println!("{:06}", 42);  // 000042

    // Right-align
    println!("{:>10}", "right");  //       right

    // Mixed
    println!("{name:>10} is {age:>3}", name = "Bob", age = 25);
}
```

สิ่งที่ควรรู้คือ format string ของ Rust รองรับ syntax มากมาย เช่น `{}` สำหรับ Display, `{:?}` สำหรับ Debug, `{:x}` สำหรับ hex, `{:b}` สำหรับ binary ซึ่งทั้งหมดนี้ถูก parse และ validate ในขณะ compile time

## แง่มุมทางเทคนิค: format_args! คือหัวใจ

สิ่งที่น่าสนใจคือ `println!` ไม่ได้ทำงานคนเดียว มันพึ่งพา `format_args!` macro ซึ่งเป็น builtin macro ของ compiler ในการสร้าง `fmt::Arguments` object

<InfoBox title="Zero-cost abstraction ของ fmt::Arguments" type="info">
  <code>fmt::Arguments</code> เป็น type ที่เก็บข้อมูลเกี่ยวกับ format string และ argument ไว้ด้วยกัน โดยไม่ต้อง alloc memory บน heap เลย (ต่างจาก <code>format!</code> ที่จะสร้าง String กลับมา) นี่คือเหตุผลว่าทำไม <code>println!</code> ถึงมี performance ดี
</InfoBox>

ความน่าสนใจอีกอย่างคือ implementation ภายในของ `fmt::Arguments` นั้นเป็น **private** ทั้งหมด ทีม Rust standard library สามารถเปลี่ยนวิธีเก็บข้อมูลภายในได้โดยไม่ต้อง break code ที่เขียนไว้ เพียงแค่ update `format_args!` macro ให้เข้ากันได้

## ข้อจำกัดที่ควรรู้

<InfoBox title="Locking ทุกครั้ง" type="warning">
  <code>println!</code> จะ lock stdout ทุกครั้งที่เรียก ถ้าใช้ใน hot loop อาจเป็น performance bottleneck วิธีแก้คือ lock ไว้ก่อน
</InfoBox>

```rust
use std::io::{stdout, Write};

let mut lock = stdout().lock();
for i in 0..1000 {
    writeln!(lock, "line {}", i).unwrap();
}
```

<InfoBox title="Panic เมื่อเขียนไม่ได้" type="danger">
  ถ้า stdout เป็น non-blocking และเกิด error <code>println!</code> จะ panic ทันที ใน production code ควรใช้ <code>writeln!</code> กับ locked writer แทน
</InfoBox>

<InfoBox title="ใช้ stderr สำหรับ error message" type="info">
  Rust convention บอกว่า <code>println!</code> ควรใช้สำหรับ primary output เท่านั้น สำหรับ error หรือ progress message ควรใช้ <code>eprintln!</code> แทน เพื่อให้ output สอง stream ไม่ปนกัน
</InfoBox>

## สรุป

`println!` อาจดูเป็นแค่ macro สำหรับพิมพ์ข้อความ แต่จริงๆ แล้วมันเป็นตัวอย่างที่ดีของ Rust philosophy นั่นคือ ใช้ macro เพื่อสร้าง abstractions ที่มี performance ดีในขณะที่ยังปลอดภัยและสะดวกต่อผู้ใช้ สิ่งที่เราเห็นเป็นแค่ `println!("hello")` ข้างหลังนั้นมีทั้ง compile-time validation, zero-cost abstraction, และ auto-borrowing ซ่อนอยู่

ใครที่เขียน Rust อยู่แล้ว ลอง `cargo expand` ดูสักครั้ง จะเห็นว่า macro ที่เราใช้ทุกวันนั้นมีความซับซ้อนและน่าสนใจกว่าที่คิด แล้วจะเข้าใจว่าทำไม Rust ถึงต้องใส่ `!` ไว้ทุกครั้ง
